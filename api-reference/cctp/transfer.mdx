Mainnet destination is Bridge Kit **`Arc`**, EVM chain `5042`, CCTP domain `26`. These identifiers are not interchangeable. Testnet uses `Arc_Testnet` and `5042002`; never send testnet assets to mainnet.

The Circle server-authorized endpoint is unavailable on mainnet because the installed Circle Wallets adapter cannot initialize Arc Mainnet. The separate browser-signed external flow can list six sources, including Base, but remains unproven end to end. Read [mainnet availability](/payments/availability).

## GET /api/cctp/transfer

Public chain metadata returns `success`, `sourceChains` and `destinationChains` on testnet. Mainnet returns `503 cctp_unavailable` before server signing because the installed adapter lacks Arc Mainnet support. `CCTP_MAINNET_SOURCES_JSON` and `CCTP_MAINNET_ARC_CHAIN_ID=Arc` do not override that compatibility gate, and testnet is never used as a fallback.

A listed source proves package/configuration selection, **not** that the signed-in consumer has a usable Circle wallet on that chain. Mainnet sources are operator-confirmed Bridge Kit names with Circle blockchain identifiers; package membership alone is not production provisioning proof.

## POST /api/cctp/transfer

Requires the database-bound consumer session and applicable `consumer.bridge` step-up. A merchant/internal key is not a replacement. The payer address is always the authenticated consumer's bound Circle wallet, not a body-supplied sender.

| Body field | Requirement |
|---|---|
| `fromChain` | Exact configured Bridge Kit source name. |
| `toChain` | Configured Arc destination name. |
| `amount` | Positive native-USDC decimal, up to 6 places, cap 10,000,000; not micro-units. |
| `recipient` | Valid destination EVM address. The current Circle path accepts this field; review it before authorization. |

The account must resolve to a supported Circle wallet with server-signing identity. Unknown wallet modes return `403 WALLET_UNSUPPORTED`; unbound Circle returns `400 CIRCLE_WALLET_UNBOUND`; external wallets return `400 EXTERNAL_WALLET` here.

<Warning>
  This account's Circle wallet was provisioned on Arc. The handler does **not** provision or bind a source-chain wallet and rejects a source whose Circle blockchain differs from Arc with `400 BRIDGE_SOURCE_UNSUPPORTED`. Do not describe this endpoint as an automatic Ethereum/Base-to-Arc source-wallet creation flow. External-wallet bridging is separate.
</Warning>

If accepted, the handler starts Bridge Kit in the background and returns `success: true`, `status: 'pending'`, `reference` and a status-polling message. That response does not prove a burn, mint or credit. There is no client idempotency key or durable Circle transfer intent in this path; tracking is process-local.

Missing session returns `401`; invalid fields/chains/amount/address return `400`; missing optional bridge credentials/configuration returns `503 cctp_unavailable`. Do not repeatedly start a new burn after a timeout or unknown reference.

## Separate external-wallet flow

The consumer bridge UI uses distinct `/api/cctp/transfer/external/...` routes for availability, preview, intent, burn verification, status and completion. Source signing stays in the wallet; the Arc destination is resolved from the server-linked Circle account. The external intent is not created by the Circle endpoint above.

`GET /api/cctp/transfer/external/availability` is a server-derived configuration check. Mainnet `configured-unverified` is not proof of settlement. `POST .../intent` reuses an identical pending/funded intent; it accepts `reference` and `retryBeforeBurn: true` only for an explicit same-intent pre-burn retry. An expired intent is not automatically replaced.

The external session must match the connected source signer. A Circle session cannot use the external intent route. The session also needs a server-linked Arc destination, and the source wallet must hold the bridge amount plus native gas. The app's preflight checks a minimum native balance; that floor is not a gas quote. Loading the page creates no intent and no burn. Complete the existing-account linking and session checks, then review fresh gas and fees before signing. Do not bypass these gates with browser control or configuration changes.

External completion binds the Iris-attested nonzero nonce to the stored burn, Arc mint and fee-adjusted recipient credit. Unique burn/mint/nonce claims prevent reuse. Status and settlement recovery do not sign; a rejected candidate hash leaves recovery open with the correct hash. Pending/unavailable attestation is retryable without a new burn. Read [recovery details](/payments/cctp-bridge).

Legacy admin-key CCTP mint/settle routes are testnet-only and return `503 cctp_legacy_mint_unavailable` on mainnet. They are not a fallback for the external Bridge Kit flow.

Inspect source burn and destination mint receipts, nonce/domain/recipient binding, actual credit and the stored intent/stages. Source gas and bridge/forwarder fees can be additional. A second bridge burn is not authorized by a pending intent or by a page reload.
