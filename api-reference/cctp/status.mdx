title: "Check or resume a Circle bridge result"
sidebarTitle: "CCTP status"

---

`GET /api/cctp/transfer/status?reference={bridge_reference}` is public and uses the reference returned by the separate [Circle transfer path](./transfer.mdx). It does not read a durable external FlowBridgeIntent.

On mainnet this endpoint reports the stored result without SDK retry or signing. A pending approval also returns without retry. On testnet, a result with an existing burn hash can resume destination-mint recovery; its source adapter is read-only and cannot submit approval or burn transactions. A submitting/error result is simply returned.

## Response

| Body state | Meaning |
|---|---|
| `success: true, state: 'submitting'` | Background submission has not returned its result. |
| `success: true, state: 'error', error` | Submission or Bridge Kit error; top-level success is lookup success. |
| `success: true, state: 'pending'` | Bridge Kit result still pending. |
| `success: true, state: 'success'` | Bridge Kit reports success; independently reconcile burn/mint/credit. |

Result-backed responses can include `amount`, `sourceExplorerUrl`, `destinationExplorerUrl` and an error message. These fields may be absent. Do not infer a verified hash or ledger write from an HTTP 200.

Missing reference returns `400`. Unknown reference returns `404` with a restart/completion caveat. Tracking is a **process-local Map**: restart or another server instance can lose visibility while money remains in flight. An unknown reference does not prove failure, completion or safety to repeat POST.

Missing bridge dependencies during testnet mint recovery return `503 cctp_unavailable`; other caught failures return `500`. Mainnet uses `Arc` (`5042`, domain `26`); bridging remains unproven end to end.

External intents use their own authenticated `/api/cctp/transfer/external/status` route for recorded state and read-only Iris mint discovery. A candidate relay hash is not completion: the complete endpoint must verify the Arc receipt. Never start a new burn because either status is unknown.
