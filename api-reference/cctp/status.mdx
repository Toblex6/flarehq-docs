title: "Check or resume a Circle bridge result"
sidebarTitle: "CCTP status"

---

`GET /api/cctp/transfer/status?reference={bridge_reference}` is public and uses the reference returned by the separate [Circle transfer path](/api-reference/cctp/transfer). It does not read a durable external FlowBridgeIntent.

When a stored Bridge Kit result is pending, the handler calls `kit.retry` on that same result. This can advance/resume the operation; it is **not a purely read-only cached lookup** or a reason to start another burn. A submitting/error result is simply returned.

## Response

| Body state | Meaning |
|---|---|
| `success: true, state: 'submitting'` | Background submission has not returned its result. |
| `success: true, state: 'error', error` | Submission or Bridge Kit error; top-level success is lookup success. |
| `success: true, state: 'pending'` | Bridge Kit result still pending. |
| `success: true, state: 'success'` | Bridge Kit reports success; independently reconcile burn/mint/credit. |

Result-backed responses can include `amount`, `sourceExplorerUrl`, `destinationExplorerUrl` and an error message. These fields may be absent. Do not infer a verified hash or ledger write from an HTTP 200.

Missing reference returns `400`. Unknown reference returns `404` with a restart/completion caveat. Tracking is a **process-local Map**: restart or another server instance can lose visibility while money remains in flight. An unknown reference does not prove failure, completion or safety to repeat POST.

Missing bridge dependencies during retry return `503 cctp_unavailable`; other caught failures return `500`. Mainnet uses `Arc` (`5042`, domain `26`); completed production bridging was not exercised in this readiness run.

The November 19 read-only Neon check confirmed the separate external intent/stage tables and found no relevant intent for the inspected accounts. This does not make the Circle Map durable or authorize a status call that might resume a transfer. No Circle status retry or new bridge was initiated.
