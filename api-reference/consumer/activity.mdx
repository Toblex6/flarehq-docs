sidebarTitle: "Consumer activity"
description: "GET /api/consumer/activity merges stored payment, swap and external-bridge records; it is not a wallet chain scan."
---

Requires a database-bound `consumer_token`. Returns `success: true` and up to **20** merged `activity` entries, newest first. No pagination or date/status filters are implemented.

## Sources and fields

| Kind | Stored source and selection |
|---|---|
| Payment | Latest 20 PaymentLog rows where `senderEmail` or `merchantSCA` equals the session wallet, then network-filtered. |
| `swap` | Latest 20 own EXECUTED FlowSwapIntent records. Reference prefix `swap:`. |
| `bridge` | Latest 20 COMPLETED external FlowBridgeIntent records whose source wallet matches. Reference prefix `bridge:`. |

All three samples are merged, sorted and truncated to 20. The Circle bridge's process-local status store is not this durable external-bridge history. Swap/bridge query failures are caught as empty arrays, so an apparently successful view can omit those records.

Entries include `reference`, `amount`, `currency`, `status`, `rawStatus`, `displayStatus`, `isExpired`, `expiresAt`, `timestamp`, `direction`, `counterparty`, `explorerUrl` and `token`. Swap/bridge entries also carry `kind`, input/output symbols and display amounts; bridges add `sourceChain`.

For payments, expired PENDING rows derive EXPIRED display status without changing the stored status. Payment `direction` is `out` when `senderEmail` equals the session wallet and `in` otherwise; it is not the initialize `send`/`request` field. Swap/bridge entries use `out` by convention, not a statement that the output token left your wallet.

Payment timestamps are row creation times; swap/bridge timestamps are update times. Display numbers and legacy token fallbacks are not exact accounting evidence. Reconcile actual token units, receipts, parties and recipient credit at fixed blocks when needed.

Missing session returns `401`; uncaught read failure returns `500`. A missing entry does not prove no transfer occurred. See [balance](/api-reference/consumer/balance) and [errors](/developers/errors).
