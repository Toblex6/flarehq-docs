---
title: "Read a consumer token balance"
sidebarTitle: "Consumer balance"
description: "GET /api/consumer/balance reads a canonical supported token on the configured Arc network."
---

Requires a database-bound `consumer_token` session. The wallet is resolved from that session, never an arbitrary address query or merchant key.

`GET /api/consumer/balance?currency=USDC` defaults to USDC and accepts case-normalized USDC, EURC or CIRBTC. The requested token must be supported on the selected network. CIRBTC is balance/swap scope only, not a merchant invoice settlement token.

Success returns `success`, `balance`, `currency`, canonical `token` (`symbol`, `address`, `decimals`) and `walletAddress`. The server reads `balanceOf` using central network configuration and token identity; old `ARC_USDC_ADDRESS` overrides are not the authority.

`balance` is `String` of a JavaScript-number conversion. It is **not guaranteed to have six fractional places** or preserve arbitrary base-unit precision. Use exact on-chain units at a fixed block for reconciliation; the endpoint does not return a block tag. USDC's native 18-decimal and ERC-20 6-decimal views describe the same asset, not separate funds.

Missing session returns `401`; unsupported currency returns `400`; a token absent from network configuration returns `400 TOKEN_NOT_SUPPORTED_ON_NETWORK`; RPC/read failures return `500`, not a fabricated successful zero balance.

```javascript
// Same-origin browser read with the existing consumer session.
const response = await fetch('/api/consumer/balance?currency=USDC', {
  credentials: 'include',
});
const result = await response.json();
if (!response.ok || result.success !== true) throw new Error('Balance read failed');
```
