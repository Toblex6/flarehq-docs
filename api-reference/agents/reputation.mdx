## Authentication

**Both GET and POST are protected** by the current key/session union: an active internal service key, active verified merchant API key, supported merchant session or database-bound consumer session. An invalid supplied key returns `401` rather than falling back to cookies. Admin cookies are not accepted here.

Authentication alone does not authorize a write as another wallet; POST also uses `verifyCallerControlsAddress`.

## GET /api/agent/reputation

Supply `agentId` (the ERC-8004 **token ID**) or `scaAddress`. When both are supplied, both constrain the stored agent lookup. No Registry-ID alias is implemented here.

Returns `success`, basic `agent`, `reputationSummary`, up to ten `recentPayments` and a message. `reputationSummary` includes:

| Field | Actual source |
|---|---|
| `estimatedScore` | SUCCESS ratio from PaymentLog rows with exact `senderEmail === agent.scaAddress`; 0 when no rows exist. |
| `totalPayments`, `successfulPayments` | Counts from that stored-payment query. |
| `totalVolumeUSDC` | Legacy name for a sum of SUCCESS row amounts, rounded to six places. |
| `reputationRegistryAddress` | Central network configuration. |

The query is not network/currency-filtered and does not read registry feedback. The volume label does not prove all underlying amounts are USDC. The score is a **payment-history estimate**, not the authoritative ERC-8004 reputation or independent trust evidence. No caller-ownership filter restricts this authenticated GET to the caller's own agent.

Missing query returns `400`; no agent returns `404`; caught read/configuration failure returns `500`.

## POST /api/agent/reputation

| Body field | Meaning |
|---|---|
| `agentId` | Required ERC-8004 token ID of a stored agent. |
| `validatorSCA` | Required feedback author's wallet, distinct from the agent owner SCA. |
| `score` | Required score within the handler's 0–100 bounds. Use a numeric value. |
| `tag` | Required feedback label. |
| `validatorWalletId` | Optional hint; must equal the server-resolved Circle wallet binding if supplied. |
| `feedbackType` | Optional legacy field passed to the contract's third numeric argument; do not infer an independently verified positive/negative classification from this name. |

The caller must control `validatorSCA`. The server resolves its Circle wallet identity and refuses missing or conflicting bindings; it does not trust a client wallet UUID as signing authority. Mainnet signing also requires a fresh Circle wallet-ID, address, blockchain and `LIVE` check; an unavailable check refuses signing rather than falling back.

The route submits `giveFeedback` on the configured registry and waits for Circle completion. Success includes token ID/name, score/tag, `feedbackHash`, validator, hash and explorer URL. There is no client idempotency key; inspect an uncertain transaction before another feedback write.

End-to-end mainnet feedback submission remains unverified. A deployment address, API response or database estimate is not an authoritative reputation score.
