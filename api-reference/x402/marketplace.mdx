**Mainnet x402 paid calls are disabled.** Listing creation/discovery does not enable payment availability. Resource routes return `503 x402_unavailable` before payment challenges.

## Endpoints and authentication

| Endpoint | Boundary |
|---|---|
| `POST /api/x402/marketplace` | Verified active merchant API key or merchant session; create a draft. |
| `GET /api/x402/marketplace` | Public published discovery. |
| `GET /api/x402/marketplace/mine` | Merchant key/session; own listings, including drafts/suspended. |
| `GET /api/x402/marketplace/{slug}` | Public for published listings; only the owner can see other states. |
| `PATCH /api/x402/marketplace/{slug}` | Owning merchant key/session. |
| `GET /api/x402/marketplace/{slug}/analytics` | Owning merchant key/session. |
| `GET/POST/PUT/DELETE /api/x402/marketplace/pay/{slug}` | Paid resource on configured testnet; disabled on mainnet. |

An internal service key alone does not satisfy the merchant resolver. Use the issued merchant key in `x-api-key` on backend requests; do not copy session cookies or expose credentials in browser code.

## Create a draft

Send JSON with these source-supported fields:

| Field | Behavior |
|---|---|
| `name` | Listing display name and default slug source. Supply it for either listing type. |
| `listingType` | Intended values `service` (default) or `agent`; do not assume unknown strings are rejected consistently. |
| `targetUrl` | Required for service listings; absolute URL checked by the SSRF guard. Stored and **exposed by public discovery**. |
| `pricePerRequest` | Required for service listings; dollar-prefixed syntax such as `$0.002`. Syntax alone is not a positive-price or token-precision proof. |
| `agentRegistryId` | Agent listing's small integer **Registry ID**, not ERC-8004 token ID or SCA address. Agent must belong to the merchant and be `ACTIVE_AGENT_PROVISIONED`. |
| `description`, `categories`, `docsUrl`, `slug` | Optional metadata; categories fall back to an empty array when not an array. Slug is normalized and collisions receive a suffix. |

Creation returns HTTP `201` with `success`, the full `listing`, draft message and applicable `payEndpoint` or `hireEndpoint`/`cardEndpoint`. New records are **DRAFT**, not payable or funded jobs.

```javascript
const response = await fetch('https://flarehq.xyz/api/x402/marketplace', {
  method: 'POST',
  headers: {
    'x-api-key': process.env.FLAREHQ_API_KEY,
    'Content-Type': 'application/json',
  },
  body: JSON.stringify({
    name: 'Example service',
    targetUrl: 'https://api.example.com/resource',
    pricePerRequest: '$0.002',
    categories: ['data'],
  }),
});
```

This is a shape example, not a tested production publish. Do not publish a secret URL or assume FlareHQ hides the upstream address.

## Public discovery and detail differ

GET discovery filters on `category`, `provider` (merchant ID), `search` and `type=service|agent`, returns `count`/`listings`, and sorts newest first. There is no source-supported pagination in this handler.

The public projection includes **`targetUrl` and `status`**, plus listing identifiers/metadata. Service entries receive `type: 'service'` and `payEndpoint`. Agent entries include separate Registry ID, ERC-8004 token ID and SCA wallet, skills/pricing, and hire/card URLs when found.

Missing agent reputation currently falls back to **50**. That number is a backend default, **not measured trust**. Do not present it as verified reputation.

Detail GET removes `targetUrl` even for an owner; it otherwise returns the saved listing, not the same enriched discovery object. A foreign caller sees non-published records as `404`. Owner `/mine` returns full own records.

## Update and publish

PATCH supports `name`, `description`, `categories`, `docsUrl`, `pricePerRequest`, `targetUrl` and `status=DRAFT|PUBLISHED|SUSPENDED`. It cannot move the listing to another merchant or agent by changing an identifier.

Setting PUBLISHED runs an SSRF/reachability check on the effective target. HEAD `405` is allowed; responses below `500`, including `4xx`, can pass. Passing this probe is **not usable-delivery or uptime evidence**.

The current publish handler applies that target check to **agent listings too**, even though agent drafts have no target URL. Therefore agent publication is not proven to work merely because draft creation succeeded; this unchanged mismatch needs separate review. Mainnet ERC-8183 hiring is also unavailable.

Missing auth is `401`; foreign ownership is `403`; missing/hidden record is `404`; invalid syntax/status is `400`; failed publish reachability is `422`.

## Configured-testnet paid resource

The resource loads a published service listing, checks target safety before charging, and auto-suspends an unsafe target with `422`, `charged: false` and `suspended: true`. Agent listings are directed to hire/card endpoints, not per-request payment.

The frozen `withGateway()` verifies and settles **before** the proxy handler. The proxy returns an HTTP **200 envelope even when upstream delivery fails**:

```json
{
  "paymentStatus": "settled",
  "upstreamOk": false,
  "upstreamStatus": null,
  "error": "...",
  "data": null
}
```

Read `upstreamOk`, `upstreamStatus`, `error` and `data`; a settled payment is not a delivery guarantee or an automatic refund. The proxy strips `payment-signature` and selected hop-by-hop headers, not a blanket credential-scrubbing rule. Use only the intended request credentials.

## Analytics limitations

Owner analytics read saved PaymentLog rows for that listing. The response includes `analytics` and the newest 25 `recentPayments`:

- `totalRequests`, `successfulPayments`, `failedPayments`, numeric `totalRevenueUSDC` rounded to four decimals and `successRate`.
- `deliverySuccessRate`, nullable when no delivery data exists, and `upstreamFailures`.
- Recent row reference, amount, status, Gateway reference, stored upstream fields, timestamp and payer label.

The Gateway wrapper records its **handler HTTP status**, whereas the proxy can return HTTP 200 with `upstreamOk: false`. Consequently stored delivery analytics can reflect wrapper success rather than actual upstream delivery. Do not treat the rate as an independently verified service reliability score. This behavior is unchanged by the docs sync.
