## Mainnet status

Authenticated mainnet calls return `503` with `code: "gateway_mainnet_unavailable"` before wallet resolution or payment. The API-key/merchant-session wrapper may return `401` first. Do not expect a `402` challenge from this convenience route.

## Authentication

Use a supported `x-api-key` or `merchant_token` session. This is **not** a public endpoint authenticated by a client-supplied payment proof. Normal merchant calls resolve the merchant's own buyer EOA. The legacy internal-service path is not a merchant integration contract; it is also blocked on mainnet.

## Configured testnet request

`POST /api/x402/pay` accepts:

| Field | Meaning |
|---|---|
| `resourceUrl` | Required absolute resource URL or same-deployment relative path |
| `body` | Optional serialized JSON string sent to the paid resource |

The current implementation pays the resource using **POST**. It does not accept `slug`, `method`, `params`, `agentId` or a client payment proof as this route's request model. A marketplace resource URL is `/api/x402/marketplace/pay/{slug}`.

The buyer must have an authorized EOA and available testnet Gateway balance. Circle SCAs cannot sign x402 payment proofs. Private keys are never part of the request or response.

## Response and delivery

The configured-testnet success response includes `success`, `transaction`, `amountUSDC`, `paidWith` and `resourceData`. A `transaction` may be a Gateway settlement reference rather than a mined hash. Marketplace `resourceData` separately reports upstream success or failure; settled payment is not an upstream-delivery guarantee.

Read [x402 protocol](/x402/overview) for the resource's base64 `PAYMENT-REQUIRED` and `payment-signature` headers. These resource headers do not replace this convenience route's authentication.
