`GET /api/jobs/{jobId}` is public, unlike the authenticated `/api/jobs?jobId=` route. It first requires a configured ERC-8183 address; mainnet without a verified dependency returns **`503 erc8183_unavailable`**. No production job payout was tested in this readiness run.

Use a protocol job-ID string, not agent Registry ID, token ID, database job ID or Telegram `job<N>` notation. Malformed integer input returns `400`; caught RPC/decode/database failure returns `500`. The handler does not independently map every missing on-chain job to `404`.

## Response

Returns `success`, `job` and nullable `database`.

| Block | Fields |
|---|---|
| `job` | `id`, client/provider/evaluator, description, human-readable USDC `budget`, ISO expiry, uppercase status, status code and hook. |
| `database` | Nullable deliverable/reason hashes, stored `txHashes` and creation time. |

The database lookup is by protocol job ID, **not scoped to an authenticated account**. Null means no stored row was found, not “no row for your account.” The hash list contains what was persisted; it is not guaranteed to be a complete chain history.

Human-readable budget formatting applies six decimals but does not guarantee six fractional characters (`"5"` is a valid formatted 5 USDC). Do not compare it directly with the raw-unit `budget` from the stored list.

Status comes from the contract's numeric code. Passing the deadline does not automatically imply an EXPIRED status code, refund or completed payout; this route has no separate `isExpired` field. Verify deadline/state before any lifecycle action.

## Evidence boundary

A successful read is not transaction, recipient-credit or exact-fee proof. Reconcile the specific receipt, token/parties/budget, balances at fixed blocks, matching row and configured explorer before making settlement claims. Public visibility does not authorize fund, submit or complete.
