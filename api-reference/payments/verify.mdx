`GET https://flarehq.xyz/api/payments/verify/{reference}` is a **public, read-only cached database view**. It requires no API key and does not submit, settle, poll Circle or independently re-read the chain. Keep sensitive application-order details outside this public invoice view.

An HTTP success or top-level **`status: true` means the record was read**, not that it is paid. Payment success is `data.status === 'SUCCESS'`. Compare the saved invoice with your order and inspect receipt/recipient-credit evidence when needed before fulfillment.

## Response fields

| Field | Meaning |
|---|---|
| `status` | Boolean query result. |
| `message` | `Verification successful` for SUCCESS; otherwise the generic pending message can appear even for other stored statuses. |
| `data.id`, `reference` | Saved invoice identifiers. |
| `data.amount`, `currency` | Saved numeric human amount and currency; do not confuse them with token base units. |
| `data.chain` | Stored chain label, not a universal enum; new mainnet invoices use `Arc v1.0`. |
| `data.status` | Raw stored payment state. |
| `data.gateway_response` | `Successful` only for SUCCESS, otherwise `Pending`; not a Gateway receipt. |
| `data.sender_email` | Stored sender label/address or null; not independently authenticated by this GET. |
| `data.merchant` | Frozen invoice display name or null. |
| `data.merchant_username` | Fresh merchant business-name lookup when `merchantId` exists; a display hint. |
| `data.merchantSCA` | Frozen recipient wallet or null. |
| `data.arcTxHash` | Stored on-chain transaction hash or null; inspect the actual receipt. |
| `data.paid_at` | Legacy **creation** timestamp, not settlement time. |
| `data.issuedAt` | The same creation timestamp, honestly named. |
| `data.settledAt` | `updatedAt` for SUCCESS, otherwise null; a database timestamp, not block time. |
| `data.expiresAt` | Stored deadline or null for historical rows. |
| `data.token`, `payToken`, `conversion` | Canonical settlement/pay-in token and saved conversion read-model; direct payments have no conversion. |

Some historical token/conversion read failures degrade to USDC or null. A display fallback is not chain evidence. New mainnet invoices are USDC-only; [Flow swaps are a separate feature](/payments/availability).

## State interpretation

`PENDING` means the invoice is recorded, not necessarily that no transaction is in flight. `SUCCESS` is stored payment success. Other paths can store processing, error, expired or batch-specific states. In particular, nano batch `SETTLED` is not the checkout success enum.

This GET does **not** expire rows. Compare `expiresAt` yourself; a never-attempted expired invoice can still read `PENDING`. Merchant links last 24 hours; initialize invoices last 120 minutes. Before replacing one, reconcile any submitted payment so you do not collect twice.

## Read-only example

```javascript
const response = await fetch(
  `https://flarehq.xyz/api/payments/verify/${encodeURIComponent(savedReference)}`,
);
const result = await response.json();
if (!response.ok || result.status !== true) throw new Error('Status read failed');
if (result.data.status === 'SUCCESS') {
  // Compare your saved amount/currency/recipient and transaction evidence.
  // Fulfill once using a durable transactional order transition.
}
```

Examples are not performed production transactions. Unknown reference returns `404` with `status: false` and `Transaction reference not found.`. An internal read failure can instead return `500` with `error`/`details`; there is no universal error envelope.

Use bounded polling and independent reconciliation. The source handler does not call the shared payments limiter, so do not assume the documented payments tier is automatically applied here. Do not use a return URL or an [unsigned webhook](/developers/webhooks) as proof of settlement.

This GET is different from `POST /api/payments/verify-onchain`: the POST can retry a pending or failed platform fee on an already successful invoice. Do not use it as a harmless read or replay probe. Historical payment/fee evidence was inspected read-only on November 19; no fee retry or proof repair was attempted. See [availability](/payments/availability).
