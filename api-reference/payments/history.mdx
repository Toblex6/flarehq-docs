`GET https://flarehq.xyz/api/payments/all` returns the authenticated merchant's stored payment rows, newest first. **`/api/payments/history` does not exist**; this documentation URL is retained for existing links.

## Authentication and scope

Use the active verified merchant's `x-api-key` or supported `merchant_token` session. An invalid supplied key does not fall back to a cookie. Rows are scoped by `merchantId`, not a business-name label.

The route implements **no** `limit`, `offset`, `status`, `from` or `to` filters, pagination, `hasMore` or total-page response. It fetches the merchant's rows and then applies network filtering; mainnet views exclude explicit historical testnet records without deleting them.

## Response

The envelope is `status`, `metrics` and `data`, not `success`/`transactions`.

| Field | Meaning |
|---|---|
| `status` | Boolean query success, not payment success. |
| `metrics.totalTransactions` | Number of network-filtered stored rows. |
| `metrics.volumeByCurrency` | Separate USDC/EURC amounts from SUCCESS rows, rounded to 4 places. |
| `metrics.totalVolume` | Deprecated mixed-unit sum; do not treat USDC plus EURC as one currency. |
| `metrics.successRate` | SUCCESS rows / all rows; defaults to 100 when there are no rows. Not independent chain evidence. |
| `data` | Formatted rows with `reference`, `amount`, `currency`, `chain`, status fields, expiration, labels and receipt fields. |

Each row includes `status`, `rawStatus`, `displayStatus`, `isExpired`, `expiresAt`, `sender_email`, `merchant`, `paid_at`, `arc_tx_hash`, `explorer_url`, `gateway_reference`, canonical `token`, `payToken` and nullable `conversion`.

Expired PENDING rows derive `displayStatus: 'EXPIRED'`; the stored `rawStatus` is unchanged. `paid_at` is the row's creation timestamp, not the settlement time. Unsupported legacy token data can degrade to USDC in this read view; do not use that fallback as proof of historical asset identity.

There is no fabricated gas-savings metric or CCTP nonce/attestation telemetry in this response. Conversion is a stored read model, not a new quote or live execution.

## Backend read example

```javascript
const response = await fetch('https://flarehq.xyz/api/payments/all', {
  headers: { 'x-api-key': process.env.FLAREHQ_API_KEY },
});
const ledger = await response.json();
if (!response.ok || ledger.status !== true) throw new Error('Ledger read failed');
// Keep ledger.metrics.volumeByCurrency as separate currency buckets.
```

This illustrative authenticated request was not run against production. A receipt hash and cached SUCCESS row should still be reconciled with the actual configured chain, parties and amount before accounting or fulfillment decisions.

Missing authentication returns `401`; read failure returns `500` with `status: false`. See [merchant profile](/api-reference/merchant/me), [verification](/api-reference/payments/verify) and [errors](/developers/errors).
