`POST https://flarehq.xyz/api/payments/initialize` creates a new `arc_ref_...` invoice with a **120-minute expiry**. Each successful POST creates a distinct reference; the handler has no client order-idempotency key. Save the reference against your order before returning the checkout URL.

**The customer pays directly to the merchant wallet; FlareHQ never holds checkout funds.** Creating an invoice stores a `PENDING` record and moves nothing. The API-key example below is illustrative, not a performed production request. [Read mainnet availability](/payments/availability).

## Authentication

The current resolver accepts:

- A verified active merchant's `x-api-key`; the server resolves that merchant's business name and payout wallet.
- An active internal service key, under separate internal-call semantics.
- A database-bound `consumer_token` session, under consumer send/request semantics.

A bare **`merchant_token` is not accepted by this initialize resolver**. Use the merchant API key here, or the separate [merchant payment-link endpoint](./payment-links.mdx), which supports the merchant session. An invalid supplied key does not fall back to a cookie. Keep keys server-side.

## Request fields

Send `Content-Type: application/json`.

| Field | Type | Behavior |
|---|---|---|
| `amount` | string or number, required | Positive human-readable decimal, up to 6 decimals, maximum 10,000,000. Prefer a string; do not send micro-units. |
| `currency` | `USDC` or `EURC` | Schema accepts these exact symbols. **Mainnet rejects EURC invoice creation**. Omitted merchant token input inherits the merchant preference; explicitly use USDC for mainnet. |
| `tokenAddress` | optional EVM address | Must match the canonical supported token; do not copy an address from a provider response. |
| `email` | optional email | Stored sender label; no guaranteed receipt-email delivery is established by this handler. |
| `merchant` | optional string | Ignored as business identity for merchant callers; used as a display label for other caller types. Not a payout destination. |
| `agentSCA` | optional EVM address | Registered agent lookup; merchant callers must own that agent. Naming it does not provision or transfer funds. The internal platform identity has separate configured semantics. |
| `webhookUrl` | optional URL | Stored destination for selected settlement notifications; unsigned/best-effort. |
| `direction` | optional `send` or `request` | Consumer flow direction; stored default is `send`. A request has no payer until settlement. |
| `payoutAddress` | optional EVM address | Consumer payout destination; omitted means the consumer's own wallet. Merchant payout remains server-resolved. |

An own-wallet consumer `request` with omitted or equal `payoutAddress` skips payment PIN; authenticated production web/assistant creation confirmed this. Consumer `send` and a request naming a foreign payout retain applicable step-up. A web foreign request returned `403 STEP_UP_REQUIRED` without creating an invoice. **Foreign request payouts are not silently discarded**.

Unsupported SDK fields include `recipient`, `successUrl`, `cancelUrl`, `metadata` and `description`. Do not assume they are stored or trigger a redirect.

## Response

The success response contains `success`, `message`, `reference`, `checkoutUrl`, `agent`, `data` and `token`.

- `data.amount` is the validated amount string; `data.currency` is canonical.
- `data.status` is **`ready`**, not the invoice's paid status. The stored invoice is `PENDING`.
- `data.authorization_url` is `/checkout/{reference}`.
- `token` contains canonical `symbol`, `address` and `decimals`.
- `agent` is null or contains available `name`, `scaAddress`, ERC-8004 `tokenId` and `circleWalletId`. It is not an interchangeable Registry ID.
- `expiresAt` is stored but not returned at the top level here; read the [verification view](./verify.mdx).

## Backend example

This illustrative request creates an invoice only; it has not been executed with an authenticated production account.

```javascript
const response = await fetch('https://flarehq.xyz/api/payments/initialize', {
  method: 'POST',
  headers: {
    'x-api-key': process.env.FLAREHQ_API_KEY,
    'Content-Type': 'application/json',
  },
  body: JSON.stringify({ amount: '0.10', currency: 'USDC' }),
});
const invoice = await response.json();
if (!response.ok || invoice.success !== true) throw new Error('Initialization failed');
// Persist invoice.reference against your order, then return invoice.checkoutUrl.
```

Missing auth returns `401`; invalid fields/token or a missing merchant payout wallet return `400`; missing agent returns `404`; foreign merchant agent or consumer step-up failures are rejected. The route uses the shared payments rate-limit tier where configured.

A cached invoice can remain `PENDING` after its deadline. Inspect any submitted payment before replacing the invoice; do not blindly replay initialization after a timeout.
