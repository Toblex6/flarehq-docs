FlareHQ is payment infrastructure for the agentic economy — an API-first Web3 payment platform that gives developers, merchants, and AI agents a complete toolkit for accepting, streaming, and programmatically controlling USDC payments — all settled on-chain on Arc Mainnet. Whether you're selling digital goods, monetizing API calls by the request, paying contractors by the second, or deploying autonomous AI agents that transact on their own, FlareHQ provides the infrastructure layer so you don't have to build it yourself.

<Note>
  **Production network: Arc Mainnet.** FlareHQ production at [flarehq.xyz](https://flarehq.xyz) runs on Arc Mainnet (chain ID `5042`, RPC `https://rpc.mainnet.arc.io`, explorer `https://explorer.arc.io`, USDC `0x3600000000000000000000000000000000000000`, 6 decimals, CCTP domain `26`). Arc Mainnet (chain ID `5042`) is the development/test environment only.
</Note>

## How FlareHQ is different

Traditional payment providers are built around fiat rails — bank accounts, card networks, and settlement delays measured in days. FlareHQ is stablecoin-native from the ground up:

| Dimension | Traditional Providers | FlareHQ |
|---|---|---|
| **Settlement asset** | Fiat (USD, EUR, etc.) | USDC on Arc Mainnet |
| **Settlement time** | 1–3 business days | Seconds (on-chain finality) |
| **Wallet custody** | Provider-custodied | Non-custodial Circle MPC wallets |
| **Agent compatibility** | None | ERC-8004 identity + ERC-8183 marketplace |
| **Micro-payments** | $0.30+ minimum viable charge | Sub-cent x402 per-request billing |
| **Payment streaming** | Not supported | Per-second USDC via ArcFlareStream |
| **Auditability** | Private ledgers | Public on-chain transaction history |

Because every payment settles on-chain, your business logic can react to payment events programmatically — no polling reconciliation jobs, no overnight batch files.

## What you need to get started

Before you write your first line of code, make sure you have the following:

- **A FlareHQ account** — sign up at [flarehq.xyz](https://flarehq.xyz). You'll verify your email and complete a brief merchant onboarding form.
- **API keys** — an API key (`arc_live_...`) for server-side calls, issued once by `POST /api/merchant/verify`. Pass it as the `x-api-key` header and never expose it in browser code.
- **Node.js 18+** (or Bun) — the `@flarehq/sdk` requires a modern JavaScript runtime.
- **USDC on Arc Mainnet** — fund your production wallet with USDC to exercise the live payment flow.

<Note>
  **Development with test funds:** Arc Testnet (chain ID `5042002`) remains available as a development/test environment with free test USDC from the Circle faucet ([faucet.circle.com](https://faucet.circle.com), select **ARC-TESTNET**). Testnet activity settles in test USDC and never moves real funds.
</Note>

## Architecture overview

FlareHQ is composed of several discrete infrastructure layers. Understanding how they fit together helps you choose the right product primitive for your use case.

| Layer | Component | Description |
|---|---|---|
| **Network** | Arc Mainnet (5042) | High-throughput EVM-compatible execution layer purpose-built for USDC settlement. RPC `https://rpc.mainnet.arc.io`, explorer `https://explorer.arc.io` |
| **Wallets** | Circle Developer-Controlled SCA wallets | Server-authorized SCA wallets — FlareHQ never exposes private keys to you |
| **Monetization** | x402 Proxy Gateway | HTTP 402 micro-settlement executor that validates payment proofs on every gated request |
| **Streaming** | ArcFlareStream | Per-second token streaming contract that distributes USDC continuously between two addresses |
| **Registry** | ERC-8004 Identity | On-chain agent identity registry — every deployed agent gets a unique on-chain ID and token |
