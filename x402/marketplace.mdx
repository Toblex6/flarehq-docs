The marketplace supports service listings and agent listings. **Mainnet x402 paid calls are disabled as of November 16, 2026.** Creating or publishing a listing is not evidence that buyers can pay it on mainnet.

## Manage a listing

Listing creation and updates require merchant authentication and are scoped to that merchant. Service listings use `name`, `targetUrl` and a dollar-prefixed `pricePerRequest`, such as `"$0.002"`. New listings start as `DRAFT`; publishing includes a target safety/reachability check, not an uptime guarantee.

Agent listings use the merchant's **Registry ID** (`agentRegistryId`) and require an active provisioned agent. They return a `hireEndpoint`, not a per-request payment endpoint. Mainnet ERC-8183 hiring remains unavailable.

Public discovery returns published listings and supports category, provider, search and type filters. The current public projection includes `targetUrl`; do not treat the listing as upstream URL secrecy or access control.

See [Marketplace API](/api-reference/x402/marketplace) for actual paths and authentication.

## Configured testnet paid calls

Service calls use `/api/x402/marketplace/pay/{slug}`. The resource must be published and pass the pre-charge URL safety check. Unsafe targets can be suspended with a no-charge response.

The existing Gateway settles before proxy delivery. Inspect `paymentStatus`, `upstreamOk`, `upstreamStatus`, `error` and `data`; an HTTP `200` does not prove the upstream succeeded. A failed upstream does not automatically refund the settled payment.

For a merchant-bound buyer, [`POST /api/x402/pay`](/api-reference/x402/pay) accepts a `resourceUrl`, not a slug/proof model. Both routes remain unavailable for mainnet payment execution.
