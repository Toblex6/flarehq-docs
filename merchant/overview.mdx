Your merchant account holds your business identity, payout wallet and API key. **The customer pays directly to the merchant wallet; FlareHQ never holds checkout funds.** Mainnet merchant invoice settlement is USDC-only.

Authenticated merchant-session link creation and hosted/embed rendering passed on November 19; existing payments were reconciled read-only. One exact checkout is approved but paused for browser attachment and a different unpaid replay target. No new payment or account/wallet-binding change was performed. Read [mainnet availability](/payments/availability) before funded use.

## Account lifecycle

| Step | Endpoint | Behavior |
|---|---|---|
| Sign up | `POST /api/merchant/signup` | Send email, business name and a password of at least 8 characters. A 6-digit verification code expires in 10 minutes. |
| Verify | `POST /api/merchant/verify` | Confirm email/code; provision the Circle payout wallet and return the one-time `arc_live_...` merchant API key. |
| Log in | `POST /api/merchant/login` | Set the 7-day HTTP-only `merchant_token` session for an active verified account. |
| Read profile | `GET /api/merchant/me` | Get masked key hint, wallet fields and a recent stored-payment sample. |
| Read ledger | `GET /api/payments/all` | Get your stored payment rows and separate currency metrics. |
| Log out | `DELETE /api/merchant/me` | Clear the cookie and attempt account session-version invalidation. |

Signup ignores bare external-wallet inputs. Link a wallet only after merchant authentication and signature proof. Keep the merchant API key in your backend secrets store; profile reads reveal only a hint. No supported separate `fhq_sec_...` checkout SDK credential or public SDK release was established in this review. See [authentication](/authentication) and [SDK guidance](/developers/sdks).

The legacy `GET /api/merchant/dashboard` API is retired with `410`. The **dashboard page** at `/merchant/dashboard` is separate and uses the profile/ledger APIs. Never expect an API response to echo your full key.

Final typecheck/build and offline/current-component checks passed; no payment behavior or stored status changed. Production deployment is not claimed. ## Payout wallet

Use [GET /api/merchant/wallet](/api-reference/merchant/wallet) with your merchant key or session. Mainnet Circle wallet checks can withhold stale/unverified addresses with `409` or retryable `503`; do not fund an address hidden by that gate.

- `PATCH /api/merchant/wallet` only switches back to Circle. It creates a **new** wallet rather than restoring an old one; already-Circle accounts with an address receive `409`.
- [GET/POST /api/merchant/wallet/connect](/api-reference/merchant/wallet-connect) links MetaMask, WalletConnect or Coinbase after a nonce challenge and wallet signature. Keep the nonce cookie across both steps. FlareHQ does not store the external wallet's private key.
- Changing the account's wallet affects future routing. Existing invoice recipient fields stay frozen; re-read the recipient before payment.

## USDC withdrawal

[POST /api/merchant/withdraw](/api-reference/merchant/withdraw) uses your authenticated Circle payout wallet, requires an `Idempotency-Key` header of 1–120 characters, and accepts `destinationAddress` and decimal `amount`. Review the address, amount and fees before authorizing an irreversible transfer.

Keep the same key for one intended withdrawal and reconcile ambiguous receipts/rows before another transfer. A PROCESSING replay with no hash is not paid and not permission to use a fresh key. External-wallet merchants manage funds in their own wallet instead.

## Create an invoice or link

- [Initialize](/api-reference/payments/initialize) uses a merchant API key, **not a bare merchant session**, and stores a 120-minute invoice.
- [Merchant payment links](/api-reference/payments/payment-links) accept a merchant key or session and store one USDC invoice with a 24-hour expiry. Links are not reusable collection addresses. `description` is echoed but not persisted.
- Open the returned hosted or embedded URL. Initialization does not charge the customer.
- Fulfill only after reconciling verified payment state and transaction evidence. [Webhooks](/developers/webhooks) are unsigned/best-effort hints, not guaranteed delivery.
