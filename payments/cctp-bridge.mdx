## Circle and external signing are separate

The [Circle server-authorized path](/api-reference/cctp/transfer) uses the authenticated consumer's bound Circle wallet. It does not provision a Base source wallet. The current consumer is provisioned on Arc and non-Arc source requests are rejected with `BRIDGE_SOURCE_UNSUPPORTED`. Its 0.100000-USDC Arc balance cannot fund or sign a Base burn.

The external browser flow requires an **EXTERNAL** consumer session matching the connected source EOA and a server-linked Circle destination on Arc. Circle sessions are refused by the external intent route with `CIRCLE_CANNOT_USE_EXTERNAL_BRIDGE`.

The link is created only when an owner-authorized, signature-verified external reconnect follows an authenticated Circle session. No reconnect or account-binding change was performed by the assistant.

Use the existing authenticated Circle account before the approved EOA's reconnect; do not create a replacement wallet. The owner reviews and signs only the authentication challenge locally, then checks the server-resolved destination preview. Do not send a PIN, code, cookie, signature or private key to the assistant. A matching database row alone does not prove the browser's active session. Linking is an owner gate, not permission to burn before the remaining checks.

## Attestation, mint and persistence

The external flow persists a `FlowBridgeIntent` **before source signing**, with the authenticated source, server-resolved destination and canonical 6-decimal amount. It verifies the source burn's destination/domain binding before advancing to `BURN_CONFIRMED`.

CCTP V2's source `MessageSent` nonce is a zero placeholder. Completion resolves Circle Iris by the **bound burn hash** and requires the nonzero **attested** nonce, source/domain/recipient binding and matching Arc mint evidence. An arbitrary USDC transfer cannot complete an intent. Where Iris supplies the relayed mint hash, the submitted hash must match it.

The Arc receipt must prove the canonical USDC credit equals gross amount minus the attested fee. Completion records `mintTxHash`, attested `cctpNonce`, measured `actualAmount` and `COMPLETED`; unique burn/mint/nonce fields prevent reuse across intents. Only completed external intents appear in activity. Stage logs are diagnostic records, not independent settlement proof.

This durable external flow is **not** the Circle path's `pendingTransfers` Map. Circle tracking is process-local and can disappear on restart or across instances; it has no durable Circle intent or client idempotency key.

## Retry and replay boundaries

- Pending or temporarily unavailable Iris is retryable (`MINT_NOT_READY`), not proof the burn failed. Retain the original reference and hashes.
- Resume the existing bridge result and evidence; **never start another burn** because a page reloaded, a request timed out or a Circle reference became unknown.
- External completion rechecks bound mint evidence and uses unique claims; a completed intent returns its saved result. Wrong/foreign evidence cannot satisfy another intent.
- [Circle status](/api-reference/cctp/status) can call `kit.retry` on a pending result. It is not a purely read-only status GET.
