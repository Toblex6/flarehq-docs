## Mainnet status

FlareHQ production reports Arc Mainnet, chain `5042`. Arc's CCTP domain is `26`; Bridge Kit identifies the destination as `Arc`.

External availability comes from `GET /api/cctp/transfer/external/availability`. Mainnet reports `configured-unverified` only when the installed Bridge Kit destination matches the server's Arc chain, domain, token and MessageTransmitter. Configuration is **not** a completed bridge; mainnet bridging remains unproven end to end.

The external flow is gated before signing: the EXTERNAL session must match the connected source signer, the session must already have a server-linked Circle destination on Arc, and the source wallet must hold the bridge amount plus native gas. An intent or an approval is not a completed bridge.

## Supported sources

The external browser flow derives Ethereum, Base, Arbitrum, Optimism, Polygon and Avalanche from the installed SDK. The app registers their chains and RPC transports from one source table and verifies the active wallet's `eth_chainId` after switching. An unsupported or mismatched destination fails closed before signing.

The separate Circle server-authorized endpoint retains `CCTP_MAINNET_SOURCES_JSON` and `CCTP_MAINNET_ARC_CHAIN_ID=Arc` for a future compatible adapter, but currently returns `503` on mainnet. Those settings do not enable the browser flow or provision a source wallet. Never substitute an EVM chain ID or CCTP domain for a Bridge Kit chain name.

## Circle and external signing are separate

The [Circle server-authorized path](../api-reference/cctp/transfer.mdx) is unavailable on mainnet because the installed Circle Wallets adapter cannot initialize Arc Mainnet. Testnet behavior remains available. It does not provision a Base source wallet, and an Arc-only Circle balance cannot fund or sign a Base burn.

The external browser flow requires an **EXTERNAL** consumer session matching the connected source EOA and a server-linked Circle destination on Arc. Circle sessions are refused by the external intent route with `CIRCLE_CANNOT_USE_EXTERNAL_BRIDGE`.

The link is created only when an owner-authorized, signature-verified external reconnect follows an authenticated Circle session. A typed destination, an unrelated connected EOA or a direct database edit is not a substitute. Use the existing authenticated Circle account before the external reconnect; do not create a replacement wallet.

Review and sign the authentication challenge locally, then check the server-resolved destination preview. Do not share a PIN, code, cookie, signature or private key. Account linking alone does not prove the browser's active session.

## Source balance and estimate

The source wallet must hold the bridge amount plus native gas for the source approval and burn. The app's preflight floor is a **minimum native balance**, not a gas quote.

Before signing, check the EXTERNAL session and linked destination, then review source gas, bridge/forwarder fees and expected destination credit. Source-chain L1 fees can be additional. Stop if the balance or estimate cannot be checked.

## Attestation, mint and persistence

The external flow persists a `FlowBridgeIntent` **before source signing**, with the authenticated source, server-resolved destination and canonical 6-decimal amount. It verifies the source burn's destination and domain binding before advancing to `BURN_CONFIRMED`.

CCTP V2's source `MessageSent` nonce is a zero placeholder. Completion resolves Circle Iris by the **bound burn hash** and requires the nonzero **attested** nonce, source/domain/recipient binding and matching Arc mint evidence. An arbitrary USDC transfer cannot complete an intent. Where Iris supplies the relayed mint hash, the submitted hash must match it.

The Arc receipt must prove the canonical USDC credit equals gross amount minus the attested fee. Completion records `mintTxHash`, attested `cctpNonce`, measured `actualAmount` and `COMPLETED`; unique burn/mint/nonce fields prevent reuse across intents. Only completed external intents appear in activity. Stage logs are diagnostic records, not independent settlement proof.

This durable external flow is **not** the Circle path's `pendingTransfers` Map. Circle tracking is process-local and can disappear on restart or across instances; it has no durable Circle intent or client idempotency key.

## Retry and replay boundaries

- Pending or temporarily unavailable Iris is retryable (`MINT_NOT_READY`), not proof the burn failed. Retain the original reference and hashes.
- Identical pending requests reuse the same intent, including after its submission expiry. A known or possible burn remains recoverable; expiry does not prove nothing was submitted.
- **Resume verification / settlement** checks the existing burn and discovers its Arc mint without source signing. You can correct an unverified hash; a server-bound burn cannot be replaced.
- **Retry approval and burn** is a separate, explicit same-intent action. Check wallet activity and confirm that no burn was submitted first. A saved burn or mint disables this action.
- Never start another burn because a page reloaded, a request timed out or a Circle reference became unknown.
- External completion rechecks bound mint evidence and uses unique claims; a completed intent returns its saved result. Wrong or foreign evidence cannot satisfy another intent.
- [Circle status](../api-reference/cctp/status.mdx) never retries signing on mainnet. Legacy testnet destination recovery cannot reopen source approval or burn.

## Verify completion

Signing must wait for the linked destination, matching EXTERNAL session, sufficient source gas and a reviewed estimate. Do not change accounts, deployed configuration or Circle Console settings to bypass a failed preflight.

After signing one burn, retain the reference and source hash. Completion must verify the source burn, Iris attestation and Arc mint with the correct parties, domains, nonce and fee-adjusted credit. Resume pending settlement from that same reference, never with another burn.

A bridge is complete only when the source burn, attestation and destination mint are verified. Uncertain settlement means stop; configuration or a local test does not establish mainnet completion.
