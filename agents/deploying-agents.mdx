`POST /api/agent/deploy` provisions Circle owner/validator SCAs and submits ERC-8004 registration. It can create wallets and spend gas. End-to-end mainnet agent deployment remains unverified.

<Warning>
  Mainnet ERC-8183 jobs and job streams are unavailable; mainnet x402 is disabled. A registered identity does not enable these features. Never fund an SCA or Gateway wallet based on older examples promising automatic job earnings or per-second salary.
</Warning>

## Authentication and request

Use the merchant's API key or supported `merchant_token` session. The authenticated merchant, not a client-supplied owner or merchant ID, owns the resulting records.

| Field | Meaning |
|---|---|
| `agentName` | Agent display name |
| `metadataUri` | Metadata URI passed to `register(string)` |
| `description`, `skills`, `pricing` | Optional descriptive/pricing data supported by the route |
| `idempotencyKey` | Optional replay key; retain it with your attempt |

Review network configuration, Circle authorization, sponsorship and the metadata before making a funded request. The registry address comes from server network configuration; the legacy `IDENTITY_REGISTRY_ADDRESS` override is not honored. Do not copy an address from a docs example into production configuration.

## What the route does

1. Checks deployment limits and an optional replay key.
2. Provisions a wallet set and two Circle SCAs: owner and validator.
3. Persists the authenticated merchant-to-wallet deployment intent.
4. Submits and polls identity registration.
5. Indexes the real token ID and persists the active agent only when identity indexing succeeds.

This is **not atomic across Circle, the blockchain and the database**. Limits and intent records reduce replay risk; they are not a claim that every crash or concurrent provisioning window is eliminated.

## Successful and pending responses

On success, save each value separately:

- `agent.id`: **Registry ID** for owner-only wallet, policy, pay and treasury routes.
- `agent.tokenId`: **ERC-8004 token ID** for identity, reputation and validation.
- `agent.scaAddress`: **SCA wallet** address.
- `agent.circleWalletId`: Circle's wallet identifier, not an on-chain agent identifier.
- `txHash`, `explorerUrl` and the owner/validator wallet addresses.

`PENDING_IDENTITY_CONFIRMATION` means registration may have succeeded but the token ID was not recovered. Preserve the transaction hash and use `POST /api/agent/deploy/recover` under the owning merchant. **Do not redeploy to recover**; that can mint another identity. No fallback token ID should be treated as active.

## Inspect status and reputation

An exact `scaAddress`-only lookup at `/api/agent/status` is public. Broader status queries by token ID, name or no filter require merchant authentication and remain scoped to that merchant.

Read [status](../api-reference/agents/status.mdx) and [reputation](../api-reference/agents/reputation.mdx) for their specific inputs. There is no universal `8004:{chainId}:{tokenId}` input accepted by every owner-only route. Missing reputation is not a default proof of trust.

## Wallet use

Circle SCAs are server-authorized treasury wallets. x402 requires a separate **EOA**, not an SCA signature, and is disabled on mainnet. [Get Test Tokens](https://faucet.circle.com) only for explicitly selected testnet development. No deployment or funding is required to read this guide.
